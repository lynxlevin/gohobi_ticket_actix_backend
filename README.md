## 設計判断

### ORMに依存したエンティティ
- ORMに依存しないエンティティにする場合、純粋なエンティティとORM用のエンティティの類似したモデルを2種類準備することになる場合が多い。その手間のメリットが大きくなるような規模の開発ではないため
- SeaORM1のマイグレーションファーストの思想により、ORM用のエンティティは自動生成することができ、手間がかからないため

### 濃いドメインサービス
- 上記のようにそもそもORMに依存したエンティティにしているため、ドメインサービスがORMに依存することは問題がない
- ORMに依存しないアプリケーションサービス層からトランザクション境界をコントロールできるようにするためには、そのための機構の実装が手間が大きい
- ドメインサービスの持つロジックを多くすることで、トランザクション境界のコントロールがしやすくなる
- ドメインサービスを濃くする上でエンティティ間の結合が強くなってしまうことには目をつぶる。マイクロサービス化などを行うような規模のサービスではないので、その結合が大きな弊害となることは考えづらい
